# 第一阶段基本能力闭环：2026-09-05

本阶段只完成 DeepSeek Harness 中火山方舟供应商的基本链路：手动配置通道、密钥引用和模型 ID，选择模型，发送文本或用户声明的图片／视频／音频，并得到正确回复或明确错误。配置、凭据、模型选择、文件上传、命令和会话生命周期尽量复用 Harness 公共接口。

## 固定合同

| 边界 | 第一阶段行为 |
| --- | --- |
| 模型 | 用户手动填写模型或接入点 ID；目录不构成白名单 |
| 模态未设置／`inherit` | 表示未知，允许请求继续，不自动填充能力 |
| `force_enable` | 只记录用户明确意图，不补齐或改变其他模态 |
| `force_disable` | 唯一因模态策略在本地阻断请求的状态 |
| Harness 模型元数据 | 省略封闭的 `inputModalities`，避免宿主提前限制未知能力 |
| Feedback／运行结果 | 只作为证据展示；成功、拒绝或 unsupported 都不改写设置 |
| 媒体 MIME | 必须由用户填写；文件名和浏览器 `File.type` 不自动带入 |
| 音频 `format` | 可由用户填写，或从用户填写的 MIME 在序列化时临时推导；不回写草稿或配置 |
| 媒体处理 | 原文件字节只做协议编码，不自动压缩、抽帧、转码或降采样 |
| 路由 | 普通 API、Agent Plan、Coding Plan 独立；不静默跨通道回退 |

供应商反馈或历史失败不能自动禁用图片、视频、音频；模型卡和示例配置也不能预填这些模态。用户无需先声明模型“支持”某模态即可尝试；服务端若拒绝，插件会保留供应商诊断并返回明确错误。

完整 Harness Web 的“安装 → 配置 → 选模型 → 上传 → 发送 → 回复”人工验收尚未完成。此前官方 Web 构建在环境中因 `tsx` IPC `EPERM` 被阻断，所以没有用组件测试替代真实 UI，也不宣称视觉或完整 Web 生命周期已经通过。

## 本地复验

本次提交仅包含基本能力代码、回归测试及下列复测证据；此前工作区额外运行的 4 项审计测试不计入本机接手后的测试数量。

```sh

pnpm run test:ci
pnpm run build

```
