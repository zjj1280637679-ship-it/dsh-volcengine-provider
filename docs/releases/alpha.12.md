# v0.1.0-alpha.12 — 清理输入区与配置卡的多余信息

本版修正 alpha.11 将实现说明和重复状态放进用户界面的问题。必要设计理由回到源码注释，重复文案删除，没有另建折叠说明面板。

## 改动

- 输入区保留附件加号，移除常驻品牌文案、供应商和模型字段。上传状态供读屏播报，目标仍可通过按钮提示确认。
- 已就绪附件由 Harness 原生标签展示；插件进度区在上传完成后退出，不常驻第二份附件详情。上传中保留已确认的字节进度和整组取消；切换模型或失败时才提示处理方法。
- 删除每组附件的引用机制说明、重复 MIME、正常状态的绑定模型行及恢复机制文案。
- 配置卡删除重复 API 地址、无设置模态摘要、密钥存储机制与供应商反馈机制说明；模型 ID、API 地址、密钥引用、模态、自定义 JSON 仍可编辑。影响选择的短提示保留。
- 本地校验错误使用可操作的短提示，不重复显示英文实现原句。未知运行错误的原文只在用户主动查看错误详情时呈现，限制长度并遮蔽常见凭据格式；正文不直接展开字段包。设置失败仍保留草稿。
- 附件合并失败时，对话仅记录本条附件未发送及简短原因；受控内部原因码写入日志。保留已接受的正文、空白和消息身份。

## 对照依据和验收原则

[ChatGPT](https://help.openai.com/articles/8400551-chatgpt-image-inputs-faq)、[Claude](https://support.claude.com/en/articles/8241126-upload-files-to-claude)、[Gemini](https://support.google.com/gemini/answer/14903178?hl=en&co=GENIE.Platform%3DDesktop) 的官方文档描述的输入流程均围绕输入、添加文件和发送。这里采用这一操作边界，不把技术解释当作附件功能，也不声称已完成它们所有功能或外观的复刻。

审查每个可见元素是否帮助用户当前操作。设计理由写代码注释，详细使用说明留项目文档，重复内容直接删除。配置字段和当前错误是产品内容；架构宣言、兼容性自述、测试结论和协议字段堆积不是。

## 验证

发布流程执行 Linux / Windows 回归、类型检查、公开 Host 契约、实际 tarball 的两次独立 Host 启动、Harness 0.1.1-rc.2 安装，以及同一个包的七次有界 Coding Plan 请求。具体候选提交、结果和校验值以本 Release 生成的附件为准。

新增和更新的回归覆盖：整个 DOM 不包含实现说明、上传完成后退出进度区且保留原生附件状态、失败仍可取消或重添、长错误包不进入默认正文、错误详情按需且有界、取消语义、附件失败不改正文空白、日志故障不阻断消息。组件验证不能代替桌面截图、IME 和实际 Host 外观验收。

## 尚未解决的宿主展示边界

- Harness 0.1.1-rc.2 和参考源码的聊天历史会把 `volcengine-image/video/audio` 自定义内容块交给 JSON 回退展示，可能露出附件内部字段。
- 忙时队列在媒体合并前可能显示 `/__dsh_volc_media_v1_…`；无法恢复附件标签时，草稿也可能保留这个标记。
- 已检查的 Host 没有块级媒体 renderer 或队列 preview 插槽。本版未接管整条消息渲染器、修改 DOM 或删除附件数据。因此本次输入区和配置卡清理，不代表历史 JSON 与队列标记已修复。

媒体原字节、三条独立通道、未知模态允许尝试、仅手动关闭才阻断、自定义 JSON 未知字段保留等合同不变。安装和实机检查见仓库的 [接手指南](https://github.com/zjj1280637679-ship-it/dsh-volcengine-provider/blob/v0.1.0-alpha.12/docs/local-handoff.md)。
