# 0.1.0-alpha.11：卡片编辑与方舟附件体验

本版集中改善实际操作：配置来源、管理模型、保留编辑位置，以及添加原始媒体时看清文件与上传状态。继续复用 Harness 的输入框、发送、排队、插话和设置服务。

## 配置卡片

- Plugins 设置页采用通道选择与当前通道详情，切换时保留各通道未保存的草稿。
- 可先保存没有模型的通道配置；未完成凭据或模型配置时明确显示未就绪，后续再添加手动模型 ID。
- 模型名称与 ID 在基础编辑区，高级参数按需展开。
- 保存与搜索保留模型及高级参数的展开状态，避免保存一次就重新寻找编辑位置。
- 模型字段错误定位到对应模型与输入项；被搜索过滤的错误模型会重新显示。
- 删除模型支持撤销，保留原位置、自定义 JSON 和其他未保存的修改。
- 保存操作及状态集中显示，继续使用独立凭据引用和原有配置并发保护。

## 输入与附件

保留彩色 `+`，明确其方舟媒体用途；宿主常驻 `+` 是命令菜单。附件入口提前显示目标模型和不可添加的原因，详情展示文件名称、类型、原始大小及上传状态。选择多个文件仍形成一组原生媒体引用，取消和删除的单位会明确说明。

文字与媒体继续由同一个原生发送流程提交。媒体按原字节上传，不压缩、转码或抽帧；模型 ID、模态和自定义请求体由用户决定。未知模态允许尝试，真实供应商反馈不自动改写模型设置。

## 验证与实机测评

发布沿用 Linux / Windows 回归、类型检查、真实 Loader 与文件设置的两次独立进程启动、旧版 CLI 安装，以及从同一 tarball 发起的最多七次真实 Coding Plan 请求。候选提交、安装包校验值和真实请求结果随 Release 附件提供。

建议按以下顺序测评：

1. 在两个通道各修改一个模型，来回切换后分别保存，确认草稿与通道归属正确。
2. 展开模型高级 JSON，保存、搜索其他模型再恢复，确认展开状态和内容保留。
3. 删除带自定义 JSON 的模型并撤销；输入重复 ID 或无效 JSON，检查错误定位。
4. 新通道先保存来源，再添加模型；确认未就绪状态与实际配置一致。
5. 添加多个原始图片、视频或音频，查看详情和进度；测试取消、删除引用及切换模型的提示。
6. 测试中文输入法、换行、普通发送、忙时排队和插话；刷新并重新启动同一个 Harness 后检查已完成附件的恢复。

这是源码、组件、Host 与真实请求层面的验证。桌面像素布局、操作系统文件选择器、IME 手感和实际启动环境由您的实机测评确认。

## 保留的边界

- 宿主的原生粘贴／拖放与方舟原字节上传仍为不同入口；本版没有通过 DOM 拦截接管它们。
- 通用 PDF、听写与实时语音需要额外的宿主或协议能力，不计作当前方舟媒体入口已支持。
- 多文件引用的操作单位仍为整组，不能把组级操作当作单文件删除。
- 刷新后的附件详情以服务端持久化摘要为准，不伪造尚未保存的逐文件信息。
- 内容寻址媒体的历史保留、会话导出及跨电脑迁移边界与 alpha.10 相同。
