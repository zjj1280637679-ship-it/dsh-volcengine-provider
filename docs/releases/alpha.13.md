# v0.1.0-alpha.13 — 让智能体真正取得已上传的源文件

本版修复一种“存在性竞态”：媒体原字节和会话引用其实仍然存在，方舟模型也能看到内容，但后续 shell、ffmpeg 或工作流工具没有可用的源文件路径，于是智能体会误判为用户没有提供文件。

## 改动

- 原生上传被合并进用户消息时，先把每个原始文件流式复制到会话工作区 `.dsh-media/<sha256>/<文件名>`，再把这条可迁移的相对路径随媒体块写入会话。模型第一轮即可使用该工作副本，后续轮次和同机冷重启不再丢失源文件位置。
- 新增 `volcengine_media_materialize` 回退工具。它只接受当前会话直接用户消息中已经存在的不透明附件 ID；工作副本被外部删除时可按需恢复，并返回绝对路径、MIME、字节数和 SHA-256。目标存在不同字节时拒绝覆盖。
- 模型请求在直接用户媒体旁加入简短 source handle，携带经过附件哈希和文件名派生校验的相对工作路径及不透明附件 ID。handle 不写入聊天历史 UI，不含插件私有存储路径；伪造或越界路径不会进入请求。
- 工作副本采用流式复制和同目录原子发布；相同内容复用，目标存在不同字节则拒绝，绝不静默覆盖。私有内容寻址对象仍是受保护的原始来源。
- 遵守会话文件策略：只读会话不自动复制，但不会阻断用户文本或方舟媒体请求；`workspace-write` 必须落在策略根目录；托管目录拒绝符号链接或 junction 绕出工作区。
- 原生上传合并收到 `user/message` 通知后，先让全部事件监听器完成入队，再调用 SessionStore 持久化 barrier。只有持久化后端明确确认时才删除 bundle manifest；无后端或 flush 失败时保留收据，避免把内存可见误认成磁盘已提交。

## 不变的边界

- 为消除源文件存在性竞态，正常可写会话会在首次模型请求前生成一份工作副本；私有内容库仍保留不可由智能体改写的原始对象。
- 不增加插件文件大小上限，不抽帧、不压缩、不转码，也不替用户自动选择模型或 API 策略。
- 工作副本解决 Harness 工具的文件可寻址性；下游工具是否接受视频、如何处理视频，仍由该工具自身接口决定。
- 设置卡、模态选择、自定义请求体和彩色 `+` 的界面行为不变。

## 回归范围

自动回归覆盖：首次请求前自动复制、同字节不同文件名的独立路径、当前轮与后续轮 source handle、伪造路径隔离、工具卸载、直接用户与工具结果隔离、跨会话拒绝、只读会话不阻断、流式副本完整性、冲突不覆盖、重复调用复用、内容库冷重启复用，以及 session flush 成功／缺失时的 manifest 退役行为。
